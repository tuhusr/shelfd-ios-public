Firestore rules note for creator public preview

This repo zip does not include the live Firebase rules file. If logged-out creator data is still blank after deploying this build, Firestore is blocking unauthenticated reads.

Add the smallest safe public-read exception for only the creator account data needed by the landing-page preview:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isSignedIn() { return request.auth != null; }
    function isCreatorPreviewUid(uid) { return uid == 'KihPpiqSsFMpn5Tee4xZWFWapg62'; }

    match /users/{uid} {
      allow read: if isSignedIn() || isCreatorPreviewUid(uid);
      allow write: if isSignedIn() && request.auth.uid == uid;
    }
    match /watchlist/{uid} {
      allow read: if isSignedIn() || isCreatorPreviewUid(uid);
      allow write: if isSignedIn() && request.auth.uid == uid;
    }
    match /publicProfiles/{profileId} {
      allow read: if profileId == 'kingkooom';
      allow write: if isSignedIn() && request.auth.uid == 'KihPpiqSsFMpn5Tee4xZWFWapg62';
    }
  }
}

Keep private collections such as messages, settings, and non-creator user data protected by your existing rules.
