Firestore rules note for Shelfd
=================================================================
Updated v806 — Email/password signup flow requires rules for the
`usernames` and `meta` collections. Without these, Auth succeeds
but Firestore writes are denied and the new account gets stuck.

Firebase Console path to edit:
  Firebase Console → (your project: track-ce817)
  → Firestore Database → Rules tab → Edit rules → Publish

Paste this complete rules file (it merges the previous creator-preview
rules + the new signup rules). Keep all your other private collections
protected by your existing rules — these only add the minimum needed
for landing-page preview, account signup, and the user counter.
=================================================================

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isSignedIn() { return request.auth != null; }
    function isCreatorPreviewUid(uid) { return uid == 'KihPpiqSsFMpn5Tee4xZWFWapg62'; }

    // ── User profile docs ────────────────────────────────────────────
    // Existing creator-preview rule kept. Authenticated users can read
    // any user doc (needed for friends / activity feed). Each user can
    // only write their OWN doc.
    match /users/{uid} {
      allow read: if isSignedIn() || isCreatorPreviewUid(uid);
      allow write: if isSignedIn() && request.auth.uid == uid;
    }

    // ── My Lists watchlist data ──────────────────────────────────────
    match /watchlist/{uid} {
      allow read: if isSignedIn() || isCreatorPreviewUid(uid);
      allow write: if isSignedIn() && request.auth.uid == uid;
    }

    // ── Public creator profile mirror ─────────────────────────────────
    match /publicProfiles/{profileId} {
      allow read: if profileId == 'kingkooom';
      allow write: if isSignedIn() && request.auth.uid == 'KihPpiqSsFMpn5Tee4xZWFWapg62';
    }

    // ── v805+ Username uniqueness index ───────────────────────────────
    // Minimal public-safe handle index used by the email signup flow.
    //  - Reads require sign-in (uniqueness check runs in the post-auth
    //    signup transaction with the user's own credentials).
    //  - Creates are only allowed for the signed-in owner, and only
    //    with the exact field set { uid, username, createdAt }.
    //  - Updates and deletes are forbidden so a username is permanent
    //    and can never be hijacked or freed by a client.
    match /usernames/{usernameLower} {
      allow read: if isSignedIn();
      allow create: if isSignedIn()
                    && request.auth.uid == request.resource.data.uid
                    && request.resource.data.keys().hasOnly(['uid', 'username', 'createdAt']);
      allow update, delete: if false;
    }

    // ── v805+ Registered-user counter ─────────────────────────────────
    // Single tiny doc bumped by saveUserProfile() when a brand-new user
    // signs up. Reads are public for the landing-page stat. Writes
    // require sign-in (the only client-side write is `increment(1)`).
    match /meta/{docId} {
      allow read: if true;
      allow write: if isSignedIn();
    }

    // Keep all your other private collections (messages, settings, etc.)
    // protected by your existing rules. Do not loosen them.
  }
}

=================================================================
After publishing the rules, the signup flow should succeed end-to-end:
  1. Firebase Auth creates the user (already working)
  2. App writes users/{uid} with onboardingComplete: false (allowed by
     the unchanged users rule above)
  3. App reserves usernames/{usernameLower} via a transaction (allowed
     by the new usernames rule)
  4. saveUserProfile() tops up the user doc + bumps meta/userCount
     (allowed by the new meta rule)
  5. Setup overlay opens at step 1

Existing orphan Auth accounts
=================================================================
If you've already attempted signups that failed before this fix, those
emails will still exist in Firebase Auth → Users. Two options:

  a) Delete them manually:
       Firebase Console → Authentication → Users → trash icon per row.
     This frees up those email addresses so the same person can sign
     up cleanly again.

  b) Leave them alone:
     Those users can still "Sign In" with their email/password. On
     first sign-in saveUserProfile() will create a minimal profile
     doc for them automatically. They won't go through the setup
     flow (no onboardingComplete:false flag), but the app will work.

Either path is fine. Going forward, the v806 signup handler cleans
up its own Auth orphans automatically (calls user.delete() if the
Firestore writes fail), so this list won't grow.
